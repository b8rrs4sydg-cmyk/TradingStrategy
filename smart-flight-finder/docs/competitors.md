# 同類服務與開源專案比較（2026-10-23 調查）

資料來源是網路搜尋的公開文章與文件，沒有逐一實測；各家宣稱的省錢比例是業者自己的說法。

| 服務 | 做什麼 | 優點 | 缺點／限制 | 我們的差異與借鏡 |
|---|---|---|---|---|
| **Google Flights / ITA Matrix** | 日期格、價格圖、價格洞察（「比平常低」）、探索地圖、價格追蹤；Matrix 可指定航線代碼、看票價組成 | 資料最完整，我們的票價就來自它 | 一次只查一個行程；不組合多趟旅程；Matrix 不能直接訂票 | 借鏡「價格洞察」：頁面新增「同航線最便宜的 X%」標籤 |
| **Kayak Hacker Fares / Skyscanner 拆票** | 兩張單程拼成來回，必要時不同航空公司 | 實測可省；只在有省時才顯示 | 行李與改票各自獨立，延誤沒有銜接保障 | **已做**：標準來回改為「拆兩張單程」比較，資料庫 3,853 組來回中 1,313 組（34%）兩張單程更便宜，中位數省 912 元 |
| **Kiwi.com（虛擬聯程 / Nomad）** | 把互不合作的航空公司拼成一個訂單；Nomad 自動排列多個目的地的順序 | 組合空間大；有延誤保障 | 轉機要自己領行李、換航廈；保障是業者自己的方案 | 我們也有跨票交接的最短轉機時間警示；Nomad 的「自動排順序」是可考慮的下一步 |
| **Skiplagged（隱藏城市）** | 目的地當作轉機點，買更遠的票 | 有時大幅便宜 | 違反運送條款，航空公司可取消後續航段與會員；不能託運行李 | **刻意不做**（風險與合規） |
| **Going / Secret Flying / Dollar Flight Club / Airfarewatchdog** | 人工加演算法找特價與錯誤票價，寄信通知 | 特價時效強 | 不是搜尋工具；錯誤票價可能被取消 | 我們的「精選 Top 100」是資料庫裡的靜態版；沒有推播 |
| **Hopper** | 預測「現在買還是等」 | 買票時機建議 | 只有手機 app；預測只是機率 | 我們有 14 筆價格歷史，尚未做預測 |
| **背包客／部落格的外站票、倒買法** | 手動：從鄰近樞紐查價，差價夠大才值得 | 實際可行 | 全手工，沒有日期與組合的系統化搜尋 | 這是我們的主要場景：把手工比價變成自動 |
| **GitHub：fli、fast-flights、gflights、flightclaw-go、flight_agent** | 包裝 Google Flights 查價（fli 支援多城市與 MCP；gflights 有 open-jaw 指令） | 開源、可程式化；fli 有重試與限速 | 都只是「查價」，沒有一個做「怎麼組合才便宜」；依賴非官方介面，隨時可能壞 | 我們的差異是組合規劃（包覆票、反向票、四腿票）加一個持續累積的票價資料庫與爬蟲 |
| **Apify 等商業爬蟲** | 付費抓 Google Flights（約 3.99 美元 / 千筆） | 免維護 | 付費、黑箱 | 我們用 GitHub 免費額度跑十隻爬蟲 |

## 從調查得到的演算法依據

* **多城市／開口票的票價結構**：業界規則是用「半個來回」的票價拼出整張票，所以通常比兩張單程便宜（尤其國際線），也與來回差不多。這解釋了我們實測「多城市票價不等於單程總和」，四腿票若由同一航空公司承擔，可以低於單程總和。據此關閉了單程總和篩選，並改以航空公司的路線網路排序。
* **拆票只有在有省時才顯示**（Kayak 的做法）：我們照做，且標明兩張票各自獨立。
* **沒有人做的**：自動組合包覆票、反向票與外站四腿票並用真實價格驗證。這是這個專案的定位，但也代表沒有現成的資料可以對照，只能靠自己的命中率統計。

## 下一步候選（依價值與成本）

1. 價格歷史預測（Hopper 式）：已有 `hist`，需要累積時間。
2. 多目的地自動排序（Kiwi Nomad 式）：開口票與倒買法的自然延伸。
3. 價格追蹤與推播：需要伺服器端儲存，目前是純靜態網站。
