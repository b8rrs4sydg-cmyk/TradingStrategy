# 開發時程與階段規劃

## Phase 1 — 專案初始化與資料庫設計 (預估 1.5 週) ✅ 本次

1. 建立前後端基礎架構，配置 Docker 開發環境。
2. 建立 2027 年台灣連假與請假攻略靜態資料庫（含法定假期、補班日、推薦特休天數）。
3. 定義資料模型：`ItineraryRequest`、`DateWindow`、`TicketStrategy`。

## Phase 2 — 核心搜尋與彈性日期展開引擎 (預估 2.5 週)

1. 日期矩陣生成演算法：根據使用者輸入的連假及 ±N 天擴展所有組合。
2. 整合第三方機票 API（Amadeus / Skyscanner），批次非同步查詢 (Asyncio) 以縮短等待。
3. Redis 快取機制：對相同航線與日期的查詢結果快取（TTL 2–4 小時）。

## Phase 3 — 進階票規演算法：反向票與四段票邏輯 (預估 3 週)

1. 反向票邏輯模組：建立航線成本矩陣，比對正反向票價差異。
2. 四段票 (Back-to-back) 配對引擎：
   - 行程拼湊演算法：「外站→台灣」與「台灣→目的地→台灣」做時間軸碰撞檢查。
   - 轉機時間合法性檢查（MCT）。
3. 計算組合後的總成本與風險提示（行李是否直掛、是否需入境轉機等）。

## Phase 4 — UI/UX 介面與最佳化推薦看板 (預估 2 週)

1. 「連假快速選單」與「多國多航段輸入介面」。
2. 結果看板：以總價 / 請假天數 / 策略類型排序。
3. Timeline View：視覺化四段票或反向票各航段的日期與銜接關係。

## Phase 5 — 測試、效能調校與部署 (預估 1.5 週)

1. 壓力測試（大量日期組合與 API 併發請求）。
2. 演算法剪枝 / 圖論最佳化。
3. 部署至雲端平台（AWS / Render / Vercel）。
